O objetivo é orientar a construção de um sistema web para gerenciamento de serviços 
automotivos, podendo ser utilizado em uma oficina mecânica ou em um lava-car. 

O sistema deverá permitir cadastrar proprietários, registrar seus veículos e acompanhar os 
serviços solicitados ou realizados. 

O projeto também permite comparar duas maneiras de acessar o PostgreSQL: 

●  Alternativa A: utilizar o pacote pg para executar comandos SQL diretamente. 
●  Alternativa B: utilizar Sequelize, um ORM que representa as tabelas por meio de 

Models e oferece métodos para consultar e gravar dados. 

As duas alternativas compartilham a mesma modelagem, regras de negócio, autenticação, 
endpoints HTTP e frontend React. Portanto, não é necessário criar dois frontends: o que 
muda é a implementação da camada de persistência no backend.

Entender o problema e definir requisitos 

Uma empresa que presta serviços automotivos precisa organizar os dados dos clientes, 
seus veículos e os serviços realizados. 

Atualmente, os registros podem estar distribuídos em planilhas, anotações ou sistemas 
diferentes. Isso dificulta localizar o histórico de um veículo, identificar seu proprietário e 
acompanhar os serviços que ainda estão em andamento. 

A proposta é desenvolver uma aplicação web que centralize essas informações. 

O mesmo sistema deverá atender a dois cenários: 

Cenário 1 — Oficina mecânica 

A empresa realiza manutenção preventiva e corretiva, troca de peças, revisão, diagnóstico e 
outros serviços. Cada atendimento gera uma ordem de serviço que registra o problema 
relatado, o serviço executado, o valor e o andamento do atendimento. 

Cenário 2 — Lava-car 

A empresa realiza lavagem simples, lavagem completa, higienização interna, polimento e 
outros serviços. Cada atendimento registra o serviço contratado, o veículo, o valor e o 
status da execução. 

A estrutura técnica será a mesma. O que muda é a descrição dos serviços utilizados no 
cadastro.

4. Estrutura do banco de dados 

A estrutura relacional será a mesma nas duas alternativas. 

O exemplo SQL cria quatro tabelas, chaves primárias, chaves estrangeiras, restrições de 
valores e timestamps utilizados nos exemplos Sequelize. 

4.1 Criar a tabela de usuários 

SQL 

CREATE TABLE usuarios ( 

    id SERIAL PRIMARY KEY, 

    nome VARCHAR(120) NOT NULL, 

    email VARCHAR(160) NOT NULL UNIQUE, 

    senha VARCHAR(255) NOT NULL, 

    perfil VARCHAR(20) NOT NULL 

        CHECK (perfil IN ('admin', 'atendente', 'tecnico')), 

    "createdAt" TIMESTAMPTZ NOT NULL DEFAULT NOW(), 

    "updatedAt" TIMESTAMPTZ NOT NULL DEFAULT NOW() 

); 

A tabela guarda as informações dos funcionários que possuem acesso ao sistema. 

A senha deverá ser armazenada utilizando bcrypt, nunca em texto puro.

5. Alternativa A — SQL com pg (sem 
Sequelize) 

Nesta opção, utilizamos instruções SQL diretamente. 

O pacote pg envia as consultas ao PostgreSQL. Os resultados de SELECT ficam 
disponíveis em result.rows. 

Não são necessários Models. 

5.1 Conexão com PostgreSQL 

Arquivo src/config/database.js: 

JavaScript 

import pg from "pg"; 

import dotenv from "dotenv";

export const pool = new Pool({

O Pool mantém um conjunto de conexões para reutilização. Isso evita abrir uma nova

5.2 Listar e cadastrar proprietários 

Arquivo src/controllers/proprietarioController.js: 

 
 
 
JavaScript 

import { pool } from "../config/database.js"; 

export const listarProprietarios = async (req, res) => { 

    try { 

        const resultado = await pool.query(` 

            SELECT id, nome, email, telefone 

            FROM proprietarios 

            ORDER BY nome 

        `); 

        return res.json(resultado.rows); 

    } catch (erro) { 

        return res.status(500).json({ 

            mensagem: "Erro ao listar proprietários." 

        }); 

    } 

}; 

export const criarProprietario = async (req, res) => { 

    try { 

        const { nome, email, telefone, cpf } = req.body; 

        const resultado = await pool.query( 

            `INSERT INTO proprietarios 

                (nome, email, telefone, cpf) 

             VALUES ($1, $2, $3, $4) 

             RETURNING id, nome, email, telefone`, 

            [nome, email, telefone, cpf] 

        ); 

        return res.status(201).json(resultado.rows[0]); 

    } catch (erro) { 

        return res.status(400).json({ 

            mensagem: "Não foi possível cadastrar proprietário." 

        }); 

    } 

}; 

 
 
 
 
 
 
 
Os marcadores $1, $2, $3 e $4 são parâmetros da consulta. 

Os valores são enviados separadamente, evitando concatenar texto recebido do usuário 
diretamente no SQL e reduzindo o risco de SQL Injection. 

5.3 Listar veículos e dados do proprietário com JOIN 

Arquivo src/controllers/veiculoController.js: 

JavaScript 

import { pool } from "../config/database.js"; 

export const listarVeiculos = async (req, res) => { 

    try { 

        const resultado = await pool.query(` 

            SELECT 

                v.id, 

                v.marca, 

                v.modelo, 

                v.placa, 

                v.ano, 

                v.cor, 

                p.id AS "proprietarioId", 

                p.nome AS "proprietarioNome" 

            FROM veiculos v 

            INNER JOIN proprietarios p 

                ON p.id = v."proprietarioId" 

            ORDER BY v.modelo 

        `); 

        return res.json(resultado.rows); 

    } catch (erro) { 

        return res.status(500).json({ 

            mensagem: "Erro ao listar veículos." 

        }); 

    } 

}; 

O INNER JOIN combina as linhas de veículos e proprietários utilizando a chave estrangeira 
proprietarioId. 

 
 
 
Assim, a API pode retornar o nome do proprietário junto dos dados do veículo.

5.6 Listar ordens de serviço com JOIN 

JavaScript 

export const listarOrdensServico = async (req, res) => { 

    try { 

        const resultado = await pool.query(` 

 
 
 
 
            SELECT 

                os.id, 

                os."dataEntrada", 

                os.descricao, 

                os."tipoServico", 

                os.valor, 

                os.status, 

                v.placa, 

                v.modelo, 

                v.marca, 

                p.nome AS "proprietarioNome" 

            FROM ordens_servico os 

            INNER JOIN veiculos v 

                ON v.id = os."veiculoId" 

            INNER JOIN proprietarios p 

                ON p.id = v."proprietarioId" 

            ORDER BY os."dataEntrada" DESC 

        `); 

        return res.json(resultado.rows); 

    } catch (erro) { 

        return res.status(500).json({ 

            mensagem: "Erro ao listar ordens de serviço." 

        }); 

    } 

}; 

Observe que agora utilizamos dois INNER JOIN. 

A primeira relação localiza o veículo da ordem de serviço. 

A segunda relação localiza o proprietário daquele veículo. 

Com isso, a listagem apresenta todas as informações necessárias sem precisar fazer várias 
requisições diferentes. 

5.7 Atualizar o status da ordem de serviço 

 
 
JavaScript 

export const atualizarStatus = async (req, res) => { 

    try { 

        const { id } = req.params; 

        const { status } = req.body; 

        const resultado = await pool.query( 

            `UPDATE ordens_servico 

             SET status = $1, "updatedAt" = NOW() 

             WHERE id = $2 

             RETURNING *`, 

            [status, id] 

        ); 

        if (resultado.rowCount === 0) { 

            return res.status(404).json({ 

                mensagem: "Ordem de serviço não encontrada." 

            }); 

        } 

        return res.json(resultado.rows[0]); 

    } catch (erro) { 

        return res.status(400).json({ 

            mensagem: "Não foi possível atualizar o status." 

        }); 

    } 

}; 

O exemplo utiliza a restrição de valores da coluna status. Uma atualização com valor 
diferente dos permitidos será rejeitada pelo PostgreSQL.

7. Autenticação, rotas e servidor 

A autenticação será igual nas duas alternativas. 

O usuário informa e-mail e senha. O backend localiza o usuário, compara a senha utilizando 
bcrypt e gera um token JWT. 

7.1 Middleware JWT 

Arquivo src/middlewares/auth.js: 

JavaScript 

import jwt from "jsonwebtoken"; 

export const autenticar = (req, res, next) => { 

    const token = req.headers.authorization?.split(" ")[1]; 

    if (!token) { 

        return res.status(401).json({ 

            mensagem: "Token não informado." 

        }); 

    } 

    try { 

        req.usuario = jwt.verify( 

            token, 

            process.env.JWT_SECRET 

        ); 

        return next(); 

    } catch { 

        return res.status(401).json({ 

            mensagem: "Token inválido ou expirado." 

        }); 

 
 
 
 
 
    } 

}; 

O middleware verifica se existe um token válido. 

Caso esteja válido, permite que a requisição continue. 

Caso não esteja válido, retorna HTTP 401.

        } finally { 

            setCarregando(false);

    }; 

    useEffect(() => { 

        carregarOrdens(); 

 
 
 
 
 
 
 
    }, []); 

    if (carregando) return <p>Carregando...</p>; 

    if (erro) return <p>{erro}</p>; 

    return ( 

        <section> 

            <h2>Ordens de serviço</h2> 

            {ordens.map((ordem) => ( 

                <div key={ordem.id}> 

                    <p> 

                        Serviço: {ordem.tipoServico} 

                    </p> 

                    <p> 

                        Descrição: {ordem.descricao} 

                    </p> 

                    <p>

                            ordem.proprietarioNome

                            Number(ordem.valor).toFixed(2) 

 
 
 
 
 
 
 
 
 
                        }

                </div> 

            ))} 

        </section> 

    ); 

};

Considerações finais 

O projeto Gestão Automotiva permite trabalhar os mesmos conceitos de desenvolvimento 
backend e frontend em dois contextos empresariais diferentes. 

Na oficina mecânica, as ordens de serviço representam manutenções, reparos e revisões. 

No lava-car, representam lavagens, higienizações e outros serviços automotivos. 

A estrutura do banco de dados, a autenticação, a API e o frontend permanecem os 
mesmos. 

 
O principal objetivo é compreender como as entidades se relacionam, como o backend 
acessa o banco de dados e como o React consome as informações disponibilizadas pela 
API. 

O aluno poderá escolher entre SQL com pg e Sequelize, mantendo os mesmos requisitos 
funcionais e resultados esperados.
